THE LANGUAGE-MODEL PROMPT STUDY

EVERY ARM, BOTH PROTOCOLS

Accuracy and macro F1 on the same frozen windows for every arm of the study. A parse failure means the model did not answer with exactly one valid class code; it counts as a wrong answer. Two arms near the top carry an asterisk of honesty: the plug-in rows score high because a trained model did the work inside them, which their detail cards spell out.

In one line: every method below is a different way of asking a language model to read 60 seconds of reactor sensor data, given as plain text, and name which of the 12 accidents is happening, with no training on this plant. The plain-words line under each method name says what that method does.

WHAT THE TRAINED MODELS SCORE (FOR COMPARISON)

The eight trained study models, run on the full held-out test split (a larger set than the 48-window language-model sample, so compare loosely). At the early protocol every approach, trained or prompted, lands near the same ceiling: twenty seconds in, ten of the twelve accidents still look almost identical.

THE PROMPTS THEMSELVES (v1 TO v4)

The exact prompt text sent for the first onset window (P100_W01), read from the study's prompt files. The later versions were built from the v1 data block: v2 explains every channel and accident in plain language, v3 adds step-by-step chain-of-thought, and v4 adds a tree-of-thoughts comparison of the three most plausible classes.
