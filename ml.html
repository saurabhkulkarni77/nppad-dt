HOW ML TAKES PLACE: ON BOARD, AT THE POINT OF CAPTURE

There is no cloud at the end of an interplanetary link, and no operator fast enough to matter. So the machine learning does not happen on the ground and it does not happen later. It happens on a small edge processor riding with the reactor, on the same clock as the accident itself. This page is the full pipeline, sensor to decision, exactly as the NPPAD-Edge payload runs it.

STAGE 01
SENSE
88 realistic plant channels sampled every 10 s. The 8 oracle leak variables are excluded: a flight sensor suite never sees them.
STAGE 02
WINDOW
The stream is aligned to accident onset and cut into fixed windows: 30 to 600 s, with 60 s the primary flight window.
STAGE 03
CONDITION
Log compression of heavy tailed channels, per channel standardisation, clipping. Fitted on training data only, frozen for flight.
STAGE 04
KERNEL FEATURES
MultiRocket and HYDRA random convolution kernels turn the window into 50,752 features. No training at this stage: the kernels are fixed.
STAGE 05
RIDGE HEAD
One linear layer scores the 12 accident classes. A softmax turns scores into the confidence figure carried in telemetry.
STAGE 06
DECIDE + ALERT
Class, confidence and mode are written to the event log and downlinked. The raw window never leaves the processor.

WHY IT FITS SPACE: THE MARS LESSON, APPLIED TO A REACTOR

No ground round trip. The Mars Society's account of autonomous rovers starts from a hard fact: signals take minutes to cross interplanetary distance, with round trips from six to more than forty minutes. A control loop that waits for Earth is not a control loop. This payload closes the loop on board, in well under a second of compute per window.

Bandwidth is precious. Early Mars radios moved less than 256 bits per second and needed an orbiter as a relay. The payload therefore downlinks only classification events (timestamp, class, confidence, mode) and keeps raw sensor windows on the device. The useful result travels; the bulk data does not.

Autonomy is the requirement, not the upgrade. Rovers became autonomous because distance forced it. A reactor on a deep space vehicle is in the same position: the diagnosis must be right, and must be made locally, whether or not anyone on Earth is awake, in contact, or in time.

Faults are expected. Radiation corrupts memory and data. The flight bundle is SHA-256 verified before load, a memory checker rehashes the live weights in flight, and a watchdog falls back to a small safe mode model rather than flying a corrupted one. Ground teams verify behaviour in advance with the digital twin, the same way rover commands are simulated before transmission.

GRACEFUL DEGRADATION: SAFE MODE

If the memory checker finds corrupted weights, or the latency budget is breached repeatedly, the payload does not stop diagnosing. It switches to a compact fallback: logistic regression on per channel summary features, a model small enough to trust when the primary cannot be trusted. Its measured test score rides in the benchmark panel. Telemetry flags the mode on every event, so ground always knows which model made the call.

DETERMINISM

The flight pipeline has no queues, no network calls and no unbounded loops. Every window costs the same fixed sequence of operations, so decision latency is a measured distribution, not a hope. The Space App page runs this exact model in your browser and times it live.

ONE HONEST CAVEAT

The confidence figure is the softmax of the ridge head's scores. It ranks classes well and matches the study's reporting, but it is an indicative score, not a calibrated probability. Mission rules should treat it that way.
