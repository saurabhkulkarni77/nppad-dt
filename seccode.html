THE SECURE CODE PROMPT BENCHMARK

A second, separate prompt-engineering study, kept alongside the NPPAD prompt study on the previous page. This one asks a different question: when a language model writes Python code, can the prompt — not the model — make the code it writes more secure? It replicates the benchmark of Bruni, Gabrielli, Ghafari and Kropp, “Benchmarking Prompt Engineering Techniques for Secure Code Generation with GPT Models” (arXiv:2502.06039, 2025).

This benchmark is a separate prompt engineering study (secure code generation) included alongside the NPPAD prompt study. It is not an NPPAD dataset result: nothing on this page comes from the nuclear plant data.

THE TASK AND THE PROMPT SET

The benchmark's combined prompt set has 202 security-sensitive Python coding prompts, drawn from two peer-reviewed datasets — LLMSecEval (Python prompts) and SecurityEval — with prompts whose suspected weakness is one MITRE lists as “can never be” filtered out. Every prompt is tagged with a suspected CWE, the class of weakness the code is most at risk of containing. The model writes a complete program for each prompt, and static scanners — Semgrep and CodeQL — then read the generated code and flag weaknesses. Two rates are reported per technique: the share of generated programs with at least one scanner finding, and the share whose findings include the prompt's own suspected CWE. A generated file that is not valid Python counts as a parse failure and is reported, not scanned.

THE TECHNIQUES UNDER TEST

Eight arms generate code for every prompt. Seven change only the prompt; the eighth feeds generated code back to the model for a review pass.

PUBLISHED RESULTS (BRUNI ET AL. 2025, GPT MODELS)

These are the paper's own numbers, measured on GPT-3.5-turbo, GPT-4o and GPT-4o-mini. They are reference values from the publication, not results produced here:

On GPT-4o and GPT-4o-mini, a security-focused prompt prefix reduced the occurrence of security vulnerabilities by up to 56% (Bruni et al. 2025).

Across the models tested, iterative prompting — the model reviewing, critiquing and improving its own generated code — detected and repaired between 41.9% and 68.7% of the vulnerabilities in previously generated code (Bruni et al. 2025).

The paper also combines its most effective techniques into a “prompt agent” showing how they can be applied in a real development workflow.

OUR REPLICATION (CLAUDE AS GENERATOR)

The same benchmark run here, with one stated difference: the paper generated its code with GPT models, and this replication generates with Claude. Same prompt set, same technique arms, same scanner-based scoring.
